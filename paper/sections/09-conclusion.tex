\section{Conclusion}
\label{sec:conclusion}

Historical confidentiality, the protection of what an agent remembered before its storage was
compromised, is a property of its own: encryption, snapshot security and history independence do
not deliver it. For content-placed indexes, induced writes label partitions with topics, and where
the layout discloses which partition holds each stored record those labels apply to records written
before the compromise; the transfer lemma makes that condition precise, and a deployed store,
pgvector under a stacked encrypted file system, meets it.

Fixed-size sealed regions with data-independent updates close the snapshot channel, and dual-epoch
security states what that buys, overflow included. Three channels reach the earlier cohort anyway:
file versions reconstruct pre-compromise writes, bounded per-partition capacity discloses the earlier
load through refusals, and an agent leaks through its own operations, down to the occurrence of a
write, which makes deduplication a membership oracle present in a widely used library.

No store whose operations depend on the content or the occurrence of what the agent does can close
that last channel. A store whose disk behaviour is a function of the clock alone can, against every
agent: placement independent of content, search in locked memory over a logical index, and a
clocked write-only-oblivious sweep, at \REtwentyoneSweepKiB~KiB per flush. Keeping headers on disk
extends it past the memory limit with its writes still invisible to a write observer.

The open problems are the ones the residuals name. A read observer of a store too large to keep
resident is defeated only by oblivious search, whose cost against these designs remains to be
measured on a common footing. Version retention at a provider is beyond the reach of the storage
layer. And a leakage claim is only as good as the granularity at which it was tested against the
bytes an adversary actually sees.
