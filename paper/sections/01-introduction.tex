\section{Introduction}
\label{sec:intro}

\IEEEPARstart{L}{arge} language model agents increasingly keep a persistent memory. While
triaging tickets, reading documents, or debugging code, an agent records what it has learned and
later retrieves relevant records by nearest-neighbor search over text embeddings
\cite{packer2023memgpt}. The records are written continuously and without human review, and the
memory is often stored on the user's own device. Over time it becomes a detailed account of the
work the agent has performed.

Security research on agent memory has so far concentrated on integrity. Poisoning attacks such
as MINJA \cite{dong2025minja}, AgentPoison \cite{chen2024agentpoison}, and MemoryGraft
\cite{srivastava2025memorygraft} insert records that alter the agent's later behavior, and the
OWASP LLM Top 10 lists vector and embedding weaknesses as a distinct risk
\cite{owasp2025llm08}. Confidentiality has received less attention. MEXTRA \cite{mextra2025}
extracts memory records through the agent's own prompting interface, and membership inference
against chat-agent memory likewise queries the running agent \cite{mrmmia2026}, but no existing
work models an adversary that obtains the storage layer. Encrypting the memory is the natural first
measure, because embeddings can be inverted to recover much of the original text
\cite{morris2023text}.

Consider a coding agent that spent the spring helping its user prepare a confidential acquisition.
Its memory folder is encrypted and synchronized to a cloud account, and in June that account is
phished. From then on the attacker receives every new version of the store, and it can email the
agent documents that the agent will read and remember. It cannot decrypt anything. What does it
learn about March?

This paper studies that adversary, which obtains the storage layer at a time $\tau$ through a
synchronization or backup account or repeated disk imaging, and holds only stored state for the
records written before $\tau$. Those records might be expected to be safer for having been written
before the breach. Our thesis is that this expectation is a security property in its own right --- \emph{historical confidentiality}, the analogue for stored
structure of what forward secrecy is for keys --- and that encryption, snapshot security and history
independence do not deliver it. \Cref{fig:overview} summarizes the four channels by which an
adversary reaches the earlier records, and the design that closes them.

\paragraph{The attack, and its precondition}
The attack rests on two properties of the setting. An agent's writes can be induced: an adversary
that supplies a document, a ticket, or an email causes the agent to write a record about it, and
that record is ordinary agent output. And encrypted vector indexes partition their records by
content, so repeated induced writes on a chosen topic reveal which partitions receive records on
that topic. Because partitions are assigned by content rather than by time, the resulting
partition-to-topic map describes the earlier records too. A transfer lemma makes this exact, and
shows the two cohorts are exposed equally, provided the adversary learns \emph{which partition holds
a given earlier record}. A layout whose regions grow with occupancy discloses that in the snapshot,
and so does pgvector's \texttt{ivfflat} index under an encrypted file system; one of fixed-size
sealed regions does not. Much of the paper is an account of how an adversary obtains that
membership anyway.

\paragraph{What actually protects, and what does not}
Subject drift erodes the transfer but does not stop it: on a timestamped issue tracker, in balanced
accuracy (which the corpus's skewed topic mix cannot inflate), the advantage falls from
\REfourAwareBal{} to \REfourNaiveBal{} when the induced content is five eras newer. History
independence is a single-snapshot notion
\cite{naor2001anti}, and two retained versions of a content-placed store diff to exactly the regions
written between them; under a real backup tool the diff names an earlier record's region at
\REnineteenPrecRatio{} times the chance rate. A store that bounds per-partition capacity and refuses
an overflowing write discloses, at AUC \REnineSilentAUCPt, that a topic's load has reached capacity,
and therefore what the earlier records contributed to it. And an agent leaks through its own
operations, down to the occurrence of a write: a memory pipeline that skips a fact it already holds
turns deduplication into a membership oracle for facts written before the compromise, which we
measure at AUC \REtwentynineQdrantPt{} in the unmodified mem0 library; it is open exactly when the
deciding model restates a stored fact verbatim, as our characterization predicts.

\paragraph{The design principle}
\emph{Semantic indexing need not imply semantic physical placement.} The adversary cannot read the
unlocked process's memory and no remote server need hold the index, so encrypted on-disk search is a
choice, not a requirement. Dropping it yields a store whose disk layout carries no content: placement independent
of content, search in locked memory over a logical partition index, and writes by a clocked sweep in
the manner of write-only ORAM. It closes all four channels against a write observer, at
\REtwentyoneSweepKiB~KiB per flush; placed under the unmodified mem0 library it takes the
membership oracle from AUC \REtwentynineQdrantPt{} to \REtwentynineMStorePt. We prove more: against a self-writing agent, a store is secure
exactly when what it reveals is independent of what the agent does, so the clock-only schedule is
not one sufficient design among many but the shape every secure design must have. Keeping headers on
disk extends the store past the memory limit with its writes still invisible to a write observer;
only a read observer needs oblivious \emph{search}, which we price rather than claim.

The contributions are as follows.
\begin{enumerate}
\item \textbf{Historical confidentiality and its threat model:} a $\tau$-arrival adversary split
into write-observing (W) and read-write (RW) classes, parameterized by version-capture granularity
and audited against the artifacts a real operating system retains
(\cref{sec:threat,sec:eval-artifacts}).
\item \textbf{Structure transfer and the channels that supply its precondition:} the transfer
attack, evaluated on deployed stores under file-level encryption and on agent-written records, and
three channels that reach the earlier cohort when the layout does not: multi-version
reconstruction, refusals, and derived writes, the last a deduplication membership oracle
measured in unmodified libraries under four models (\cref{sec:transfer,sec:eval}).
\item \textbf{Dual-epoch security:} an adaptive, leakage-parameterized definition; sufficient
conditions that cover overflow; separations from forward/backward privacy, breach resistance and
history independence; and a reactive variant with an exact characterization of the stores secure
against a self-writing agent (\cref{sec:dualepoch,sec:eval-game,sec:eval-reactive}).
\item \textbf{A design space, implemented and audited:} three designs and a larger-than-memory
variant, a byte-level auditor, and registered measurements of every channel, including those that
stay open (\cref{sec:mnemos,sec:eval}).
\end{enumerate}

\Cref{sec:background,sec:threat} cover related work and the threat model, \cref{sec:transfer}
the attacks, \cref{sec:dualepoch} the theory, \cref{sec:mnemos} the designs, \cref{sec:eval} the
measurements, and \cref{sec:discussion} the limitations.
