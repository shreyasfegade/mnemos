\Cref{tab:crossscheme} places the designs among the alternatives. Against the write observer W, a
write-only oblivious index closes every channel, and Mnemos-M/disk matches it by writing on a clock;
Mnemos-M also removes the disk from the query path, which makes search and query equality
\emph{absent} rather than oblivious. Against the read observer RW only full obliviousness closes
search and query equality, at a per-access cost: the ORAM-based systems (compared in the
supplementary material) are the reference for that stronger adversary, not a baseline this work
claims to beat, and they buy read-side obliviousness a write observer does not need.

\subsection{Residual Leakage}

Mnemos-P's residuals are those of \cref{tab:crossscheme}: an open write channel, query equality,
a permutation a read observer recovers, version diffs closed only across sessions, and derived
writes. Mnemos-M's
clock is visible, so an observer learns when the store was open though not whether anything was
written; without back-pressure, a lock after a burst the sweep could not place reveals that the
backlog exceeded the journal. The guarantees cover the store's own files: an agent framework that
persists other state whose writes follow the agent's decisions must keep it in the store or outside
the observed scope (\cref{thm:reactive}). Both Mnemos-M variants inherit A3: if the adversary can read process memory, a
memory-resident index is the worst place to have put the plaintext, which is why hibernation is a
deployment requirement. No storage-layer measure reaches copies a synchronization provider has
already retained.

\subsection{Limitations}

\paragraph{Assumptions}
The analysis depends on A2, a clean host before $\tau$, and A3, that the adversary cannot read
process memory. Decrypted results and the embedding computation reside in process memory; the locked
region holds plaintext during an operation, and for the memory-resident design for the whole
session, but the Python embedder sits outside it, so plaintext embeddings may reach swap on the
embedding path.

\paragraph{Agent experiments}
The agent results use local models of moderate size, and the induced corpus is issue text from one
public tracker. The deduplication oracle is measured end to end in mem0 only, with one 7B model
deciding; the other frameworks the census flags, and frontier-scale models, were not run.

\paragraph{Scope of the measurements}
Performance is measured on one machine (Intel i9-14900HX, 32\,GB, NVMe, Windows~11, with WSL2 for
the stacked encrypted file system). The deployed-store experiments use local instances holding public
data under one encryption layer, over three store builds each, and their per-store conclusions
depend on library versions. The version-granularity parameter is swept rather than measured against
a provider's retention policy. Performance is measured to $10^5$ records, and retrieval with a second
embedding model on two domains only. Key custody is implemented for Windows only.

\paragraph{Construction}
Both sealed designs remove a tombstoned record only when the maintenance cursor reaches its region.
Records larger than one payload block are rejected rather than chunked. The partition table is fixed
at creation, so a store whose subject matter drifts far enough eventually partitions poorly. Rebuilding
it is not evaluated: for Mnemos-P a rebuild rewrites every region and a corpus-trained table would
violate S4, while Mnemos-M's logical table could be retrained in memory without a disk write.

\subsection{Ethical Considerations}

The attacks were run against implementations built for this study and against public or synthetic
corpora; no third-party production system was attacked, and the deployed stores and library of
\cref{sec:eval-real,sec:eval-dedup} were local instances holding public data. The countermeasures
are layout changes designers of encrypted indexes can adopt, and are disclosed with the attacks.
